# Практическая работа № 2. Тест-дизайн

Вариант 2: прокат велосипедов.

## Правила и тестовые данные

| Правило | Проверяемые значения | Ожидаемый результат |
| --- | --- | --- |
| Аренда от 1 до 10 часов включительно, 120 рублей за час | 1, 5, 10 | 120, 600, 1200 рублей |
| Недопустимый срок | -1, 0, 11 | IllegalArgumentException |
| Имя после удаления крайних пробелов имеет длину 2–25 | 2, 10, 25 символов | Имя принимается |
| Недопустимое имя | null, пустая строка, только пробелы, 1 и 28 символов | IllegalArgumentException |
| Удаление крайних пробелов | «  Анна  » | «Анна» |
| Внутренние пробелы сохраняются | «  Анна  Мария  » | «Анна  Мария» |
| Сначала удаляются пробелы, затем проверяется длина | 25 букв с двумя пробелами с каждой стороны | Принимаются 25 букв |
| Длина проверяется после удаления пробелов | « А » | Ошибка: остаётся один символ |
| Просрочка только при возврате позже срока | На секунду раньше, точно в срок, на секунду позже | false, false, true |
| Без опоздания штраф отсутствует | Аренда на 1 час, возврат раньше и точно в срок | 0 рублей |
| При опоздании штраф составляет половину стоимости | Аренда на 1, 5, 10 часов; возврат на секунду позже | 60, 300, 600 рублей |

## Как выбирались тесты

Разбил входные данные на классы эквивалентности: допустимые и недопустимые сроки, допустимые и недопустимые имена, своевременный и запоздалый возврат. Внутри допустимых диапазонов взял обычное значение, а возле границ проверил оба края и значения за ними: 0/1 и 10/11 часов, 1/2 и 25/28 символов.

Для времени проверил три случая вокруг назначенного срока. Равенство времени особенно важно: по условию оно не означает опоздание. Для имени отдельно проверил порядок действий и сохранение внутренних пробелов.

## Реализация

`BikeRental` содержит четыре метода:

- `rentalCost(hours)` проверяет срок и считает стоимость.
- `registerName(name)` удаляет крайние пробелы, проверяет имя и возвращает его.
- `isLate(dueAt, returnedAt)` сравнивает время возврата с назначенным сроком.
- `lateFee(hours, dueAt, returnedAt)` возвращает половину стоимости при опоздании, иначе ноль.

Задание не задаёт тип и текст ошибки, поэтому для неправильного срока и имени выбран `IllegalArgumentException`. Тесты проверяют тип ошибки, а не придуманный текст. Используются целые часы и рубли; 50% от 120 рублей всегда даёт целое число. Время передаётся явно через `LocalDateTime`, без обращения к текущим часам. Отсутствующее время считается ошибкой вызова, это дополнительная защита метода, а не отдельное правило задания.

Регистрация здесь означает проверку и подготовку имени. Хранение клиентов, база данных и интерфейс заданием не требуются.

## Запуск

Нужен JDK 25 или новее. Из папки `02`:

```bash
sh ./mvnw test
```

Windows:

```powershell
.\mvnw.cmd test
```

В IntelliJ IDEA открой папку `02` как Maven-проект, дождись загрузки зависимостей и запусти `BikeRentalTest` кнопкой рядом с классом. JUnit запускает тесты, а AssertJ проверяет результаты через `assertThat(...).isEqualTo(...)` и исключения через `assertThatThrownBy(...).isInstanceOf(...)`; Maven Wrapper входит в комплект.

## Проверка тестов с намеренными ошибками

В отдельной временной копии убрал верхнюю границу срока: упала 1 проверка. Затем сделал возврат ровно в срок запоздалым: упали 2 проверки. Заменил половину стоимости на полную стоимость штрафа: упали 3 проверки. Это показывает, что тесты обнаруживают ошибки в этих правилах. Рабочий код не изменялся; результаты находятся в `logs/mutation-check.json`.
