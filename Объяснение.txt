Практическая работа № 1 по тестированию ПО. Второй вариант.

Метод EstimatePolicy.minutes получает число баллов и возвращает минуты.
Каждый балл равен 15 минутам. Допустимы значения от 1 до 8 включительно.
Условие points < 1 || points > 8 проверяет обе границы: || означает «или».
Если аргумент недопустимый, throw выбрасывает IllegalArgumentException.
Если аргумент допустимый, return points * 15 возвращает результат.

Всего 8 тестов: 4 исходных и из разбора, 4 для второго варианта.
Проверки варианта: 4 -> 60 минут; 7 -> 105 минут; -2 -> исключение;
11 -> исключение и сообщение "points must be between 1 and 8".
Для 4 баллов в задании есть противоречие между 45 и 60. По формуле верно 60.

@Test отмечает метод, который запускает JUnit. В тесте создаём объект,
вызываем проверяемый метод и сравниваем ответ с известным ожиданием.
assertEquals принимает сначала ожидаемое, потом фактическое значение.
Эталон получаем из задания, а не через вызов проверяемого метода.
assertThrows проверяет, что действие выбрасывает нужное исключение
или его подкласс. Лямбда () -> ... передаёт отложенное действие.
Возвращённое исключение можно сохранить и проверить error.getMessage().

Порядок демонстрации:
1. Показать правило и условие в EstimatePolicy.java.
2. Показать тесты для 4, 7, -2 и 11 в EstimatePolicyTest.java.
3. Запустить весь класс: ожидается 8 успешных тестов.
4. До изменения объяснить: если убрать верхнюю границу, тест для 11
   упадёт, потому что метод вернёт 165 вместо исключения.
5. Временно оставить if (points < 1), сохранить файл и запустить класс.
   Упадут тесты для 9 и 11. Показать elevenPointsAreRejectedWithMessage.
6. Вернуть if (points < 1 || points > 8), сохранить и снова запустить.
   Все 8 тестов должны пройти. Ожидания в тестах не менять.

Запуск из папки 01:
macOS / Linux: sh ./mvnw test
Windows PowerShell: .\mvnw.cmd test
Нужен JDK 25 или новее. Первый запуск требует сети для загрузки зависимостей.
В IDEA открыть папку 01 как Maven-проект и нажать зелёную кнопку у класса.
Для импорта можно использовать встроенный Maven; синхронизировать проект.

Логи трёх запусков находятся в logs/. Исходный успех: run-success.log;
ожидаемое падение: run-failed.log; восстановление: run-restored.log.
Счётчики соответственно: 8/0/0/0, 8/2/0/0, 8/0/0/0
(Tests run / Failures / Errors / Skipped).
Failures означают несовпадение с ожиданием, Errors — непредвиденные ошибки,
Skipped — пропуски. Сборка с нулём запущенных тестов не подтверждает проверку.

На защите: «В работе проверяется один класс. Ожидания взяты из требований.
После удаления верхней границы соответствующие тесты падают. После
восстановления реализации проходят. Это показывает обнаружение данного
дефекта». Отдельный main не нужен: тестовые методы запускает JUnit.
Эти тесты не проверяют интерфейс, базу данных или сеть.
