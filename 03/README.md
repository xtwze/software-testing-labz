## Что проверяется

Сервис `TaskService.create` удаляет внешние пробельные символы из названия, проверяет дубликат у конкретного владельца, создаёт задачу с UUID и временем из переданных часов, затем вызывает хранилище.

`TitlePolicy` выполняется по-настоящему. `TaskStore` заменён моком Mockito: база данных и сеть в этих тестах не используются. Тесты проверяют логику сервиса и его обращения к хранилищу, а не работу настоящей базы.

| Тест | Что проверяет |
| --- | --- |
| savesNormalizedTaskWithOwnerAndTime | Базовое сохранение: название, владелец, время, UUID и возвращённый объект |
| invalidTitleDoesNotTouchRepository | Пробельное название отклоняется до любых обращений к хранилищу |
| duplicateIsNotSaved | Дубликат вызывает исключение и не сохраняется |
| normalizedDuplicateDoesNotReachSave | В поиск дубликата передаётся название без внешних пробелов |
| creationUsesTheClockPassedToTheConstructor | Сервис использует отдельно переданные часы из шага 6 |
| savesReviewAndroidForBob | Вариант Б, задание 1: сохраняются `Review Android` и `bob` |
| rejectsNormalizedDuplicateForBob | Задание 2: дубликат `  Review Android  ` ищется по нормализованной строке и не сохраняется |
| tabsAndNewlinesDoNotTouchStore | Задание 3: `\t\n` вызывает ошибку без обращений к хранилищу |
| savesTaskAtVariantBTime | Задание 4: время сохранения равно `2026-10-03T18:30:00Z` |

## Как запускать

Нужен JDK 25 или новее. Открой папку `03` в IntelliJ IDEA как Maven-проект. Дождись загрузки зависимостей и запусти `TaskServiceTest` зелёной кнопкой рядом с классом.

Если зависимости подсвечены красным: Maven → Sync All Maven Projects. Если импорт через wrapper не срабатывает, выбери встроенный Maven в Settings → Build Tools → Maven и повтори синхронизацию.

Из терминала в папке `03`:

```bash
sh ./mvnw test
sh ./mvnw '-Dtest=TaskServiceTest' test
```

Windows PowerShell:

```powershell
.\mvnw.cmd test
```

После первого успешного скачивания зависимостей можно использовать `sh ./mvnw -o test`.

В `pom.xml` подключены JUnit, AssertJ и Mockito. Surefire запускает тесты с агентом Mockito; путь к нему вычисляется через `${settings.localRepository}` и заключён в кавычки. Для непосредственного запуска из IDEA используется её конфигурация запуска JUnit; настройка агента в Surefire относится к запуску через Maven.

## Что сказать на защите

«Я тестирую сервис отдельно от базы данных. Передаю ему мок хранилища и фиксированные часы через конструктор. Настраиваю ответы хранилища, вызываю сервис, затем проверяю результат и обращения к зависимости».

- `@ExtendWith(MockitoExtension.class)` подключает Mockito к JUnit.
- `@Mock TaskStore store` создаёт тестовую замену хранилища перед каждым тестом.
- `when(store.exists(...)).thenReturn(true)` задаёт ответ о наличии дубликата. Это подготовка, а не проверка.
- `thenAnswer(call -> call.getArgument(0))` возвращает объект, переданный в `save`. Сам мок ничего не хранит.
- `ArgumentCaptor` позволяет посмотреть, какой объект сервис передал на сохранение.
- `verify(store).save(captor.capture())` проверяет ровно один вызов и захватывает аргумент. Повторного сохранения здесь нет.
- `assertThat(...).isEqualTo(...)` сравнивает фактическое значение с ожидаемым.
- `assertThatThrownBy(...)` проверяет исключение от переданного действия.
- `Clock.fixed(...)` фиксирует время; тест не зависит от сегодняшней даты.

### Почему для неверного названия нужен verifyNoInteractions

При неверном названии сервис должен остановиться до любых обращений к хранилищу. Проверка `never().save(...)` запретила бы только запись, но пропустила бы ненужный вызов `exists`. Поэтому для строки `\t\n` используется `verifyNoInteractions(store)`.

Для дубликата всё иначе: сервис обязан спросить `exists`, поэтому полное отсутствие взаимодействий требовать нельзя. Здесь проверяются точные аргументы `exists` и отсутствие `save`.

### Зачем отдельно проверять часы

Если заменить `clock.instant()` на `Instant.now()`, в задаче окажется текущее системное время вместо `2026-10-03T18:30:00Z`. Тест обнаружит это расхождение. Ожидаемое время задаётся явно, а не считывается из результата сервиса.

### Порядок демонстрации

1. Покажи `TaskStore`, затем конструктор `TaskService`: зависимость передаётся снаружи.
2. Покажи четыре действия в `create`: нормализация, поиск дубликата, создание объекта, сохранение.
3. Покажи четыре теста под комментарием «Вариант Б».
4. Запусти класс `TaskServiceTest`.
5. Объясни разницу между `when`, `verify` и утверждениями AssertJ.
6. Для демонстрации ошибки временно замени `exists(owner, title)` на `exists(owner, rawTitle)`, запусти тесты и затем восстанови код. Не меняй ожидания тестов под ошибку.

| Запуск | Тестов | Падений | Ошибок | Пропущено |

| Время берётся через Instant.now() | 9 | 3 | 0 | 0 |
| Правильный код восстановлен | 9 | 0 | 0 | 0 |

Эксперименты выполнены в отдельной временной копии. Тесты не подгонялись под ошибки. Рабочая версия содержит правильную реализацию.

При передаче `rawTitle` упали `normalizedDuplicateDoesNotReachSave` и `rejectsNormalizedDuplicateForBob`: вместо ожидаемого `IllegalStateException` возник `PotentialStubbingProblem`. Mockito обнаружил, что стаб настроен для строки без пробелов, а сервис передал строку с пробелами.

После подмены часов упали три проверки времени: `savesNormalizedTaskWithOwnerAndTime`, `creationUsesTheClockPassedToTheConstructor`, `savesTaskAtVariantBTime`. Фактическое системное время не совпало с явно заданным ожидаемым моментом.

Полные сообщения сохранены в `logs/`. В `summary.json` указаны числа проверок, коды завершения и SHA-256 итогового тестового файла. Локальные пути в логах заменены на `<project>` и `<home>`. Финальный запуск завершился `BUILD SUCCESS`.
